# hh_apply

Локальный агент откликов на вакансии hh.kz **под вашим личным аккаунтом**.
Открывает видимое окно браузера, ищет вакансии по `keywords.yml`, отбрасывает
то, куда откликаться нельзя или не надо, показывает каждую карточку с
письмом целиком — и отправляет только то, что вы явно подтвердили.

**Это не источник лидов.** Воркер ничего не шлёт в ядро лидгена: нет
`core_client`, нет `POST /companies/ingest`, нет HTTP-клиента вообще — наружу
он ходит только браузером на hh. Ядро он не трогает и не импортирует; ни ядро,
ни другие воркеры не импортируют его, а playwright есть только в его
`requirements.txt`. Всё это проверяется разбором кода в
`tests/test_isolation.py`, а не обещанием.

---

## ⚠️ Честно про риск для аккаунта

Агент действует **от вашего имени, под вашей учётной записью hh**. Автоматизация
откликов — это то, на что hh может отреагировать ограничениями (капча, лимиты,
в худшем случае — блокировка), и никакой темп этот риск до нуля не снимает.
Что сделано, чтобы он был минимальным:

- **темп намеренно человеческий**: пауза между откликами — случайная из
  `APPLY_DELAY_SECONDS` (по умолчанию 20–30 с; меньше 10 с не принимается),
  пауза между страницами — `BROWSE_DELAY_SECONDS` (3–6 с);
- **не больше `MAX_APPLIES_PER_RUN` откликов за прогон** (по умолчанию 20, потолок в коде 50);
- **капчу агент не решает никогда**: увидел `/account/captcha` — останавливает
  прогон и поднимает окно;
- **вторая ошибка подряд останавливает прогон** — что-то изменилось, пусть посмотрит человек;
- окно всегда видимое, действия замедлены (`SLOW_MO_MS`), чтобы вы видели, что
  происходит, и могли закрыть окно.

Решение пользоваться этим — ваше.

## Что делать по шагам

```bash
# 0. Зависимости (playwright — только для этого воркера)
pip install -r workers/hh_apply/requirements.txt
python -m playwright install chromium
cp workers/hh_apply/.env.example workers/hh_apply/.env       # впишите MY_NAME

# 1. Вход РУКАМИ. Пароль агент не видит и не хранит.
python -m workers.hh_apply.login
```

Откроется окно; войдите в hh как обычно. Скрипт сам заметит вход (или
`--enter` — ждать Enter в консоли) и запишет `session/session_signal.json`:
какие ключи состояния страницы вакансии появляются **только под аккаунтом**.
Это health-check каждого прогона. Куки протухают незаметно: страницы
открываются, а отклики молча перестают уходить — проверка «страница
загрузилась» такое пропускает, проверка «признаки аккаунта на месте» — нет.

```bash
# 2. Разведка формы отклика (один раз; и заново, если hh поменяет форму)
python -m workers.hh_apply.probe --from-search          # или --url https://hh.kz/vacancy/<id>
```

Проба открывает форму отклика, нажимает «Добавить сопроводительное» и
записывает, что появилось: `evidence/<дата-время>-open-form.json` плюс два
HTML-дампа модалки. **Отправить в этом прогоне ничего нельзя физически**:
любой не-GET запрос обрывается на уровне сети. Найденный селектор
переносится в `hh_selectors.py` вместе с именем файла измерения — см.
«Поле сопроводительного письма» ниже.

```bash
# 3. Письмо и запросы
cp workers/hh_apply/cover_letter.example.md workers/hh_apply/cover_letter.md   # перепишите своими словами
#    keywords.yml — что искать и какие слова в названии исключать

# 4. Сухой прогон — режим по умолчанию, ничего не отправляет
python -m workers.hh_apply.main

# 5. Отправка: и флаг, и слово в подтверждении
python -m workers.hh_apply.main --send
```

## Как работает один прогон

```
health-check сессии (session_signal.json) ── протухла → стоп: «войдите заново»
поиск hh по keywords.yml (обычная страница поиска в вашем окне) → id вакансий
для каждой вакансии (пауза BROWSE_DELAY между страницами):
    открыть страницу, прочитать её состояние (HH-Lux-InitialState)
    стопы (gate.py) → skipped / needs_manual
    собрать письмо из cover_letter.md → не собирается → needs_manual
    открыть форму отклика (всё ещё только GET) → узнать форму, прочитать резюме и слова hh
карточки → вы вводите номера → слово «отправляем»
для каждого одобренного (пауза APPLY_DELAY между откликами):
    открыть заново, перечитать negotiations.total → уже есть → skipped
    окно в сети только на эту вакансию → форма → письмо → прочитать обратно → отправить
    открыть заново → negotiations.total ≥ 1 → sent, иначе «hh не подтвердил»
```

### «Откликался ли уже» — числом

```
applicantVacancyResponseStatuses["<id>"].negotiations.total >= 1
```

Не по наличию кнопки (на откликнутой вакансии «Откликнуться» нет — там «Отклик
другим резюме», hh разрешает повторный отклик) и **не по ключу
`alreadyApplied`** — он врёт: в WWAO измерено `total == 1` при
`alreadyApplied == false`. Проверяется **перед каждым кликом** (страница
открывается заново прямо перед отправкой — журнал может отстать, hh нет) и
**ещё раз после отправки** (новой загрузкой: состояние hh запечено в документ,
старая страница показала бы старые числа). Непонятная форма ответа — не «0», а
`needs_manual`.

### Что останавливает отправку — только проверяемые факты

| факт | исход |
|---|---|
| отклик уже есть (`total ≥ 1`, или непустой список переписок) | `skipped` |
| вакансия в архиве / закрыта для откликов | `skipped` |
| у работодателя тест — на тесты отвечает человек | `needs_manual` |
| нужно письмо, а его нет (`cover_letter.md` отсутствует или пуст) | `needs_manual` |
| письмо длиннее лимита hh для этой вакансии | `needs_manual` (не обрезаем) |

Слова hh в форме («такой отклик может получить отказ…», «поменяйте видимость
резюме…») отправку **не** останавливают — в WWAO вторая фраза сутки считалась
отказом, и это было неверно: отклик с ней уходит (измерено 2026-09-07). Они
показываются на карточке и пишутся в журнал.

### «Не знаю» уходит человеку

Всё, что агент не узнал, — `needs_manual`, а не догадка:

- счётчик откликов или условия отклика в незнакомой форме, hh противоречит сам себе;
- на странице нет известной кнопки «Откликнуться», или её href ведёт на другую вакансию;
- в форме отклика есть элемент, которого не было в измерении (радиокнопки,
  вопросы, выбор резюме, второе поле) — форма сравнивается с эталоном из `evidence/`;
- после «Добавить сопроводительное» появилось не то поле, что в измерении, или
  селектор поля нашёл не ровно один элемент, **или поле не нашлось вовсе**;
- в поле после ввода оказался не тот текст, что вы подтвердили;
- hh подставил в форму другое резюме, чем было на карточке;
- после отправки hh не подтвердил отклик — это «не удалось подтвердить», а **не**
  «не отправлено»: запрос ушёл, проверьте руками, прежде чем отправлять снова.

Вернуть вакансию в очередь после того, как разобрались: `python -m workers.hh_apply.main --requeue <id>`.

### Подтверждение

Каждая карточка показывает, **что именно уйдёт**: вакансию, компанию, ссылку,
id, резюме, которое подставил hh (прочитано из открытой формы — это ничего не
отправило), что hh написал в форме, замечания к письму (ссылка, `@`) и **письмо
целиком**. Вы вводите номера тех, на которые отправить (`все` — все), и
набираете слово «отправляем». Пустая строка, другое слово, Ctrl-C, закрытый
ввод — не уходит ничего. Флага, отвечающего на вопрос за вас, нет.

### Сетевой предохранитель

Отклик уходит не когда нажата кнопка, а когда из браузера уходит запрос —
поэтому охраняется сеть. Весь прогон **любой не-GET запрос обрывается**, кроме
как внутри окна, которое открывает ваше подтверждение для одной конкретной
вакансии; внутри окна обрывается всё, что называет другую вакансию. Service
workers в браузере заблокированы — иначе перехват видел бы не всё.

## Сопроводительное письмо

Шаблон — **файл `cover_letter.md`**, не `.env` (многострочный текст в `.env`
ложится плохо). Это ваш личный текст — он в `.gitignore`; заготовка —
`cover_letter.example.md`.

| плейсхолдер | откуда |
|---|---|
| `{position}` | название вакансии со страницы hh (`vacancyView.name`) |
| `{company}` | название компании со страницы hh (`vacancyView.company.visibleName`) |
| `{my_name}` | `MY_NAME` из `.env` |

- нет файла / пустой (HTML-комментарии не считаются) → `needs_manual`, ничего не печатается;
- опечатка в плейсхолдере (`{compnay}`) или пустой `MY_NAME` → письмо не собирается
  (это ошибка настройки: вакансия не записывается в `needs_manual`, а прогон
  говорит, что исправить);
- hh не назвал компанию или вакансию → `needs_manual` — «Здравствуйте, !» хуже никакого;
- подстановка — только известных имён, одиночные `{` в тексте не мешают;
- перед отправкой письмо показывается в карточке целиком.

### Поле сопроводительного письма: статус измерения

В WWAO это был единственный незакрытый пробел: поле прячется за кнопкой
«Добавить сопроводительное», её textarea не попала ни в один дамп. Здесь
селектор не угадывается — `LETTER_FIELD` в `hh_selectors.py` принимается только
вместе с файлом измерения, в котором этот самый запрос записан как проверенный
на живой странице (нашёл ровно одно поле, появившееся после клика, и текст в
нём читается обратно). Пока такого файла нет, агент не отправляет ничего.

### Измерено 2026-09-11 — и что НЕ измерено

**Поле письма: НЕ измерено.** Разведка на живой форме не проведена: вход в
hh в окне агента дважды не состоялся — оба раза окно 15 минут простояло на
странице входа (`evidence/20260911-123239-login-signal.json`,
`evidence/20260911-142012-login-signal.json`; в первом файле ещё нет поля
`profile_read_on`, и его «ключи профиля» сняты со страницы входа, а не с
вакансии). Поэтому в `hh_selectors.py` `LETTER_FIELD.query` пуст и
`MEASURED_BY = None`, и **агент не отправит ни одного отклика**: `--send`
отказывает на старте, сухой прогон пишет «НЕ ОТПРАВИТСЯ, пока не исправлена
настройка». Селектор не угадан намеренно — ни `textarea`, ни `data-qa` из
памяти.

Закрыть пробел — два запуска с вашим входом:

```bash
python -m workers.hh_apply.login --enter      # войти в ОКНЕ АГЕНТА (Chromium), потом Enter в консоли
python -m workers.hh_apply.probe --from-search
```

Проба напечатает `MEASURED_BY = '<дата-время>-open-form'` и
`LETTER_FIELD.query = '...'` — это переносится в `hh_selectors.py` (у
кнопки, модалки, отправки и «Добавить сопроводительное» — тот же
`MEASURED_BY`). Проверка селекторов сама откажет, если вписанный запрос не
из списка, проверенного пробой.

**Что измерено** (`evidence/20260911-anonymous-state.json`, свежий профиль,
вакансия 136457688): у анонимного посетителя
`applicantVacancyResponseStatuses["<id>"]` **есть** и непуст (условия отклика),
но **без `negotiations`**; `userLabelsForVacancies` = `{"<id>": []}`;
`userId` = `null`; `account` / `hhidAccount` — словари из `null`. Следствия:

- правило WWAO «эти два ключа непусты — значит, вошёл» (запасная ветка
  `agent/login.py`) для свежего профиля неверно: первая версия `login.py`
  записала «вошёл» для анонима. Признак удалён; теперь вход подтверждается
  только разницей с анонимной базой, которая меряется каждый раз в
  одноразовом браузере без кук, а пустота проверяется рекурсивно;
- на анонимной странице `negotiations` нет → «откликались ли уже» = «не знаю» →
  `needs_manual`. Разлогиненная сессия не может прочитаться как «не откликались».

## Файлы

```
hh_apply/
├── browser.py      # playwright: видимое окно, свой профиль, сетевой предохранитель, переходы по hh
├── login.py        # вход руками + session_signal.json + health-check
├── search.py       # поиск через UI hh по keywords.yml (только ссылки /vacancy/<id>)
├── page_state.py   # чтение состояния страницы: negotiations.total, условия, название, компания
├── gate.py         # стопы перед откликом
├── letter.py       # шаблон письма, плейсхолдеры
├── hh_selectors.py # селекторы + проверка по файлам измерений, эталон формы
├── probe.py        # разведка формы отклика и поля письма → evidence/
├── submit.py       # форма, письмо, отправка, переспрос hh
├── confirm.py      # карточка подтверждения в консоли, номера, слово
├── journal.py      # SQLite-журнал и кто какой статус может менять
├── main.py         # точка входа
├── config.py       # .env, пути, темп
├── keywords.yml    # что искать (area: 160 — Алматы, 159 — Астана; с api.hh.ru/areas/40)
├── cover_letter.example.md
├── requirements.txt, .env.example
└── tests/
```

`hh_selectors.py`, а не `selectors.py`: модуль с именем `selectors` внутри
пакета мог бы подменить одноимённый модуль стандартной библиотеки, на котором
стоит asyncio (и playwright).

**В `.gitignore`**: `session/` (профиль Chromium с вашей живой сессией и признак
входа — самый чувствительный каталог), `evidence/` и `screenshots/` (страницы,
открытые под аккаунтом), `*.sqlite3` (какие вакансии вы откликали),
`cover_letter.md` (ваш текст). Журнал хранит sha256 письма, не само письмо.

## Что взято из WWAO и что сверх

Перенесено подходом, не копированием (`Who_wants_an_offer/agent/` не
изменялся): видимое окно и вход руками; health-check по признакам аккаунта;
`negotiations.total` вместо кнопки и `alreadyApplied`; стопы только по фактам;
«не знаю» — человеку; журнал с правами на переходы; сетевой перехват; капча по
адресу, а не по словам; региональный редирект hh после входа.

Сверх: сопроводительное письмо (шаблон, плейсхолдеры, разведка поля); узнавание
формы по эталону из измерения; предпросмотр формы до подтверждения (резюме и
слова hh на карточке); поиск через UI hh вместо очереди из бэкенда.

## Тесты

```bash
pytest workers/hh_apply/tests
```

Без браузера и без сети: страница hh — на моках (`tests/fakes.py`), форма
состояния — та, что измерена в WWAO. Покрыто: подстановка плейсхолдеров и
поведение без шаблона; разбор `negotiations.total` (включая врущий
`alreadyApplied` и форму, которая «не 0, а не знаю»); стопы; `needs_manual` при
неузнанной форме, ненайденном поле письма, лишнем элементе, другом резюме,
несовпавшем тексте — и что кнопка отправки при этом **не нажата**; проверка
до и после отправки; сетевой предохранитель; проверка селекторов по файлу
измерения; изоляция от ядра и других воркеров.
